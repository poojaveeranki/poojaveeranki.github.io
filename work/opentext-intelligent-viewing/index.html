Integrating OpenText Intelligent Viewing into a React application

OTDS authentication, publication service, token management, viewer initialisation and publication status polling, with product-level issues escalated to OpenText support.

  • React
  • OpenText IV
  • Brava
  • OTDS

Context

An enterprise application built in React needed to let staff view and annotate documents without leaving the application. The document platform was OpenText Intelligent Viewing, with the Brava viewer on the front end and a set of OpenText services behind it: publication, asset, markup, search and viewer services, with OTDS providing authentication.

My part was a combination of implementing the React side, troubleshooting across the service boundary, and coordinating with the vendor when a problem turned out to be theirs.

What I did

  • Integrated the Brava viewer loader into the React application and wrapped it in a reusable BravaViewer component, handling the asynchronous bravaReady initialisation.
  • Configured HTTP headers for authenticated viewer requests and integrated OTDS tokens, with a small token manager to cache and refresh them.
  • Worked with the viewer API: setting HTTP headers, search and markup hosts, enabling markup, choosing a layout, adding a publication and rendering.
  • Integrated the publication service so that uploaded files could be published for viewing, and added publication status polling.
  • Integrated the markup service for annotations.
  • Tested the integration end to end alongside the development work.

What went wrong and how it was found

Publishing rejected local file paths. The publication service would not accept a local path for a blob. Investigation showed it needed a physically reachable file location, which led to exposing an upload endpoint through a file-server plugin and then working through 404 responses from the publication service until the flow held.

Missing authorisation headers. Some asset service requests went out without the authorisation header. Tracing how headers propagated through the viewer's requests, together with cross-origin configuration, resolved it.

A GraphQL error from the markup service. Annotations failed with a non-nullable field error on the text of a markup. After isolating it to the service rather than the integration, I raised it with OpenText support. The vendor confirmed a known product defect, fixed in Intelligent Viewing 25.1 and in a retrofit for 24.2.

What I learned

Most of the time went not into writing the integration but into finding where a failure actually lived: the React code, a header, a service configuration, or the product itself. Being able to say "this is the vendor's bug, here is the evidence" and get it confirmed was worth more than any workaround.
